# SOP生成スキル

入力（ファイルパスまたはテキスト説明）から、業務を知らない人でもそのまま実行できる精度の
SOP（標準作業手順書）Excelファイルを生成する。

## 入力

`/sop` の引数として以下のいずれかを受け取る：

- **ファイルパス**：.md / .docx / .xlsx / .pptx / .pdf / .txt など。Readツールや抽出ツールで内容を読む
- **テキスト説明**：業務フローの説明文をそのまま解析する
- 引数がない場合：「どの業務のSOPを作りますか？ファイルパスか説明文をください」と聞く

## 処理手順

### Step 1：入力の解析

入力から以下を抜き出す：

1. **目的**：この業務は何のために存在するか
2. **登場人物**：誰が関わるか（担当バトンの列展開に使う）
3. **手順**：時系列のタスク分解（1行動＝1行）
4. **暗黙知**：「詳細」「注意点」「備考」欄などに埋まっている判断基準・失敗パターン・コツを見つけ、該当する列（分岐条件・失敗時対応・前提条件など）に振り分ける

### Step 2：13列への展開

各タスク行に以下の13列を**必ず全部**埋める：

| # | 列名 | 内容 |
|:---:|:---|:---|
| 1 | 番号 | 連番（分岐がある場合は 3a / 3b のような枝番も可） |
| 2 | タスク（行動） | 1行動を動詞で。「〜を確認する」「〜を送信する」 |
| 3 | 担当バトン | 誰がやるか。登場人物が複数いる場合は人物ごとに列を展開してもよい（○を付ける方式） |
| 4 | 情報（必要書類・データ） | このタスクに必要な書類・データ・URL・ファイルの場所 |
| 5 | チェックリスト | 実行時に確認する項目（複数あれば「・」区切り） |
| 6 | TODO（具体的な次アクション) | 今すぐ手を動かせるレベルの具体的アクション |
| 7 | 期間（最短・目安） | 「最短○分／目安○日」形式 |
| 8 | 完了判定 | 「何が起きたら次へ進んでよいか」を観測可能な事実で書く |
| 9 | 分岐条件 | 「〜の場合は番号○へ」形式。分岐がなければ「分岐なし→次へ」 |
| 10 | 定型文・雛形 | そのまま使えるメール文・記入例。長い場合は要点＋別セル参照 |
| 11 | 失敗時対応 | 何が起きたらどう戻すか・誰に連絡するか |
| 12 | 証拠・記録 | 何をどこに残すか（ファイル名・保存先・スクショ等） |
| 13 | 前提条件 | このタスク開始前に満たしておくべきこと |

**埋め方の原則：**
- 入力に情報がなくても「該当なし」とは書かない。AIの推定案を**「（推定）」付き**で入れる
- 完了判定は必ず観測可能な事実（「メールが届いた」「画面に○○と表示された」）で書く
- 知らない人が読む前提。社内略語は初出時に補足する

### Step 3：Excel生成

openpyxlで生成する。書式：

- 1行目：タイトル（業務名＋「SOP」）、2行目：目的、3行目：作成日・作成者（Claude Code）
- 5行目：ヘッダー行（13列。背景色付き・太字・折り返し）
- 6行目以降：タスク行（全セル折り返し・上揃え）
- 列幅：番号=6、タスク=30、担当=12、それ以外=25〜40で内容に応じて調整
- ヘッダーに固定表示（freeze panes）を設定
- 罫線あり・行の高さ自動

生成後、`python scripts/recalc.py` は不要（数式を使わないため）。

### Step 4：保存と報告

- 保存先：`G:\マイドライブ\ObsidianVault\MyVault\幸せ貢献業\SOP\YYYY-MM-DD_業務名_SOP.xlsx`
- 業務名はファイル名規則に従う（スペースなし・記号なし・内容がわかる名前）
- 同名ファイルがあれば `_1` `_2` と連番を付ける
- 保存後、SendUserFileでファイルを送付する
- 報告は5点フォーマット（実装内容・価値対応・動作確認・懸念点・次タスク）で簡潔に

## 注意

- Vault保存はExcelファイル本体のみ（.md化はしない。SOPはExcelが正本）
- 元の入力ファイルは編集しない（生ソース保護）
- 内容に個人名・金額・契約情報が含まれる場合は、報告時に「機密情報を含む」と一言添える
