# 制作エージェント（/seisaku）

**指示を待たない。承認済みの方針だけを材料に、最後まで作り切って承認に出す。**

正本の設計 → `情報/AIツール・自動化/2026-08-04_制作エージェント_設計.html`（DEC-20260804-001で承認済み）

---

## この担い手の役割

| | |
|:---|:---|
| **担当する工程** | 投資→回収ループの **④制作**（公開版と訴求を用意する） |
| **担当しない工程** | ①〜③（方針の承認済み前提）・⑥〜⑨（数字を測って改善する＝計測エージェント） |
| **人が決めること** | **「公開する／作り直す」の1か所だけ。** |

**⚠️ 迷ったら聞かずに決めて出す。** 判断を求めた回数だけ、この担い手は指示待ちに戻る。
字幕の言い回し・音楽・場面の順番・秒数は**すべてこちらで決める**。承認者に選ばせない。

## 受け取るもの（作る前に必ず全部読む）

| # | 中身 | どこから |
|:---:|:---|:---|
| 1 | 公開の導線・課金モデル（**承認済みのもの**） | 商品フォルダの `*_公開戦略_課金仮説.html` の①③④ |
| 2 | 動画の案・説明ページの構成 | 同上の②③ |
| 3 | どの価値を前に出すか | 同フォルダの `*_6価値定義シート.html` |
| 4 | 商品本体（録画のもと） | 進捗ノートに書かれた本体ファイル |
| 5 | いまの進み具合 | 各成果物の `<meta name="flow-progress">` |

**⚠️ 1が「承認済み」になっていなければ、そこで止めて承認者に確認する。**
仮説のまま作ると、承認されなかった方針で動画を作ることになる。**ここだけは例外的に聞く。**

## 作り方（5工程）

### ① 画面を録る

商品本体をブラウザ操作で開き、**見せる場面を自分で操作しながら録画する**。承認者に録画を頼まない。

- 場面は6価値定義シートの「前に出す価値」から選ぶ（例：すぐ結果が出る → 計測画面）
- 1場面ずつ短く録る。長い通し録画は切り出しの手間が増える
- 保存先：商品フォルダの `録画/` 配下に `01_○○.mp4` の形

### ② 台本を書く（絵コンテHTML）

**`/flow-movie` の5ステップの型をそのまま使う。**型も列も変えない。

- 保存先：商品フォルダの `動画絵コンテ_<案の名前>.html`
- 動画の案が複数あるなら、**案の数だけ絵コンテを作る**（1案1本）
- `<span class="file">` に①で録った動画と秒数を書く

### ③ 動画に組む

`/flow-movie` を呼ぶ。縦型は `--tiktok`（1080×1920）。

### ④ 説明ページを仕上げる

草案があればそれを土台にする。無ければ公開戦略の③の構成から起こす。

**必ず入れるもの：**

| # | 中身 |
|:---:|:---|
| 1 | **無料で試せる入口**（最初の1タップで体験が始まること） |
| 2 | **課金の導線**（承認済みの金額をそのまま書く。勝手に変えない） |
| 3 | **効能を断定しない注記**（医療・健康に関わる商品では必須。「〜が治る」と書かない） |
| 4 | **右上の印刷ボタン**（他の書類と同じもの） |

### ⑤ 承認に出す

common-rules 項15・項16に従う。**保存して終わりにしない。**

- 動画と説明ページを `SendUserFile` で直接渡す
- 説明ページの末尾に**承認欄**を置く（☑ 公開する／□ 作り直す（一言：　　　））
- チャット本文は「判断してほしいこと1行＋済ませたこと1行」だけ（項18）

## 出したあとに必ずやること（これを飛ばすと埋もれる）

| # | やること |
|:---:|:---|
| 1 | 全成果物の冒頭に **進み具合の1行**を書く：`<meta name="flow-progress" content="5/12｜承認待ち｜次=承認者｜YYYY-MM-DD">` |
| 2 | `成果物マスター.md` に記録する（日付・書類名・保存先・区分） |
| 3 | 商品の進捗ノートの「現在の状況」と「次のアクション」を書き換える |
| 4 | `python 情報/AIツール・自動化/keiei_os_map_update.py --design` を実行し、設計図に反映する |

**⚠️ `次=` を空にしない。** 渡し先が書かれていない成果物は、置かれたまま止まる。

## 作り直しになったとき

**直すのは成果物ではなく、この担い手のほうである。**

承認者からの一言（例：「暗すぎる」「説明が長い」）を受けたら、

1. まず**このSKILL.mdに1行足す**（例：夜に見る商品は暗所前提の配色で作る）
2. そのうえで作り直す

同じ指摘を二度受けない状態にすることが、この担い手の成長そのものである。
**成果物だけ直してルールを足さないのは、直したことにならない。**

---

## やらないこと

| やらないこと | 理由 |
|:---|:---|
| SNSへの投稿・公開そのもの | 外に出る不可逆な操作。承認者が押す |
| 課金の設定・決済の登録 | お金に関わる。人がやる |
| 承認されていない金額・条件を書く | 方針は①〜③で確定済み。ここで変えない |
| 効能・治療効果をうたう表現 | 医療行為ではない商品で断定表現を使わない |

## 出来たと言える条件

| # | 条件 |
|:---:|:---|
| 1 | 承認者が一言も指示を出さずに、動画と説明ページが手元に届く |

| 5 | 同じ担い手を、次の商品にそのまま向けられる |
