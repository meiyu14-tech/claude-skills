# 業務フローの仕上げ（/flow-shiage）

**フローは骨組み。実際に動くと書類が生まれる。その書類を「使う瞬間の場所」へ貼り戻すと、フロー1枚が「何をするか」と「そのとき使う実物」の両方を持つ。**
担当者が変わっても、ステップを上から辿るだけで必要な書類に全部届く。**これが属人性を消すということ。**

書類を「種類」や「フォルダ」で整理してはいけない。**新しい人は「どのフォルダを見ればいいか」を知らない。**
だが「いま自分はステップ3にいる」は誰でも分かる。**使う瞬間で並べれば、知識のない人でも辿れる。**

---

## 仕上がった状態（これが目標）

```
◆ 経営設計図 ⑤商品設計
✓ ⑤-1      経営OSの導入の流れ          ← 押せる（フロー本体）
   ⑤-1-1   許可と題材の記録            ← 文字だけ。一段下げる
   ⑤-1-3a  見立てシート
   ⑤-1-3b  実物の依頼文
   ⑤-1-6a  地図（受注から収支まで）
   ⑤-1-6b  打ち合わせの進め方
   ⑤-1-7   月次の数字づくり
   ⑤-1-8   社長面談の段取り

◆ フロー本体（⑤-1）の「使うもの」欄
   ステップ3： 借りた管理資料／設定⑥ 入口＋合言葉／📄 3a シート／📄 3b 依頼文
   ステップ6： 会社の地図／📄 ⑤-1-6a 地図／📄 ⑤-1-6b 打ち合わせの進め方
```

**番号を見れば居場所が分かり、フローを開けばその場で書類に飛べる。**両方が揃って初めて仕上がり。

---

## 手順

### 1. 実際に何が生まれたかを洗い出す

そのフローの全ステップについて、**実際にやった行動と、そこで生まれた／使った書類**を並べる。

**⚠️ 「相手に送るものが無い」＝「アクションが無い」ではない。**
社内で許可を取る・題材を決めるのも立派なステップ1の行動で、その記録は残っている。

**⚠️ 相手に送った「画面」も書類として数える。**
URLを送った時点で、それは相手の手に渡った成果物である。**設定欄にURLが書いてあることと、フローに書類として載っていることは別。**
設定欄は「この会社ではどこか」を書く場所であって、**そこに書いたからフローに載せた、ことにはならない。**

| よくある取りこぼし | 実体 |
|:---|:---|
| 回答画面・入力画面のURLを送った | **相手が触った成果物。**番地を付けてステップに貼る |
| 合言葉つきの入口を伝えた | 同上。入口そのものが書類 |
| 打ち合わせ用の画面を画面共有した | 同上 |

**探し方：**「相手に何を送ったか」を時系列で全部並べ、**1つずつフローの中に居場所があるかを見る。**

#### 毎回この6つを聞く（省略しない）

**思い出そうとしない。聞いて確かめる。**記憶に頼ると必ず抜ける。

| # | 質問 | どこを見れば裏が取れるか |
|:---:|---|---|
| 1 | **相手に送ったURL・画面はあるか**（回答画面・入力画面・合言葉つきの入口） | 進捗ノートの「送付済み」「配置完了」 |
| 2 | **相手に送った文面はあるか**（メール・チャット） | 案件フォルダの `NN_◯◯文.md` |
| 3 | **相手に見せた資料はあるか**（画面共有・印刷して持参） | 議事録・打ち合わせの記録 |
| 4 | **相手から返ってきたものはあるか**（回答・実物・赤字） | 生ソース・受領ファイル |
| 5 | **社内で作った記録はあるか**（許可・題材・段取り） | 案件の記録（正本） |
| 6 | **上の1〜5は、いま全部フローのどこかに居場所があるか** | フローの「使うもの」欄 |

**⚠️ 4（返ってきたもの）を忘れやすい。**送ったものだけ見て終わると、**相手が答えた事実が記録から消える。**

### 1-2. 「相手に渡したもの」の欄をフローに作る

**送ったものは、こちらの手元に何も残らない。**メールやチャットで送った瞬間に完結してしまうから、
**記録に残す欄を先に作っておかないと、必ず抜ける。**

フローの末尾に置く。**画面だけに出し、印刷には出さない**（管理のための欄であり、打ち合わせに持って行く紙ではない。A3の余りも無い）。

```html
<section id="watashi" class="noprint">
<h2>この流れで相手に渡したもの</h2>
<table><thead><tr>
  <th>渡した日</th><th>渡したもの</th><th>番地</th><th>ステップ</th><th>相手が返してきたもの</th>
</tr></thead><tbody>
  <tr><td>2026-07-27</td><td>答え合わせの入口（画面）＋合言葉</td><td>⑤-1-3c</td><td>3</td><td>○×の回答</td></tr>
</tbody></table>
</section>
```

**この欄は機械の検査対象。**番地が空の行、または経営設計図に無い番地は `--design` が知らせる。

```
⚠️ 渡したのに番地がありません: 2026-07-27 答え合わせの入口（画面）＋合言葉
   → ⑤-1_経営OSの導入の流れ.html のステップに貼り、経営設計図にも登録する
```

**⚠️ 渡した直後にこの欄へ1行足す。**「あとでまとめて」にすると、何を送ったか思い出せなくなる。

### 2. 番号を決める

| 種類 | 番号 | 例 |
|---|---|---|
| フロー本体 | 経営設計図の箱の中の位置 | ⑤-1 |
| そのステップで使う付属品 | **親の番号 + ステップ番号** | ⑤-1-6（ステップ6で使う） |
| 同じステップに2つ以上 | **枝番 a/b** | ⑤-1-6a／⑤-1-6b |

**⚠️ 番号は経営設計図上の居場所を指す**（DEC-20260730-010）。フォルダ構成とは切り離す。

### 3. 経営設計図に登録する

箱の `data-files` に1行足す。書式は **`パス|表示名|段|ステップ番号`**。

- **段**＝2 で一段下がる（親の下に入る）
- **ステップ番号**を書くと、番地が「親の番地-ステップ番号」になり、**自動でリンクなしの文字だけ表示**になる

**⚠️ 表示名に古い番号やカッコ書きの説明を入れない。**番号は機械が前に付ける。

### 4. フロー本体の「使うもの」欄に貼る

| 記号 | 何に使うか |
|:---:|---|
| **📄** | **押せるもの。**`業務フロー/` にあってサーバーに配ってある書類だけ |
| **・** | **押せないもの。**記録（正本）の中にある .md など。番号だけ出す |

**⚠️ この欄に書くのは番号だけ。書類の名前は書かない。**（2026-07-31・承認者のメモ）

```
使うもの ： 借りた管理資料／📄 ⑤-1-3a／📄 ⑤-1-3b／📄 ⑤-1-3c
詳細　　 ： … 3a＝見立てシート（紙）／3b＝実物の依頼文／3c＝答え合わせの入口（合言葉）
```

**理由：**「使うもの」欄はいちばん狭い。名前を入れると折り返して**行が縦に伸び、A3に収まらなくなる。**
**何なのかは詳細欄で分かればよい。**番号は押せば開くので、名前は欄の中では役に立たない。

**⚠️ 名前を詳細欄へ移すときは、同じ行の別の文を同じだけ削る。**
行の高さは**その行でいちばん高い欄**で決まるので、詳細欄が伸びれば行も伸びる（実測：足しただけで2mm超過した）。

**このフローは携帯で読まれる。**だから「押して開けるか」が実際に効く。
📄 なら現場でステップを追いながらその場で実物を出せる。**・ なら「パソコンで探すもの」だと分かって迷わない。**

**⚠️ 会社ごとに変わるURLは、設定欄から取って貼る。**本文に直書きすると2社目で書き換え漏れになる。
設定欄のリンクに `id` を付け、ステップ側のリンクの行き先を**画面を開いたときに設定欄から写す**（数行のスクリプト）。**設定欄だけ書き換えれば動く**状態を保てる（共通ルール項17）。

**⚠️ 押せないリンクを作らない**（共通ルール項15・16）。**押して開かないと、人はそこで止まり、理由も分からない。**
**⚠️ 全部を📄にしない。**配る＝商品の部品として他社にも渡るということ。
他社にも使い回す書類だけHTMLにして配り、**1社限りの記録（許可の経緯・面談の段取りなど）は配らない。**

### 貼り忘れは機械が知らせる

書類を作っても**フローに貼り忘れると誰も辿り着けない**（経営設計図に出ていても、フローを上から追う人には見えない）。
`--design` が、番地が「親-ステップ」の形の書類について、親フローの「使うもの」欄に出ているかを検査する。

```
⚠️ フローに貼られていません: ⑤-1-6b_打ち合わせの進め方.html
   → ⑤-1（⑤-1_経営OSの導入の流れ.html）の「使うもの」欄に足す
```

**書類を作ったら `--design` を回す。**貼り忘れがあればその場で名前と貼る先が出る。**人の記憶に頼らない。**

### 5. 名前を5か所そろえる

**ここで必ず事故が起きる。**2026-07-30に同じ抜けを3回繰り返した。

| # | 直す場所 |
|:---:|---|
| 1 | ファイル名 |
| 2 | `<title>` |
| 3 | `<h1>` |
| 4 | フローの「使うもの」欄の**表示ラベル**（href だけ直して表示を忘れる） |
| 5 | 経営設計図の `data-files` の**表示名** |

**⚠️ リンク先（href）を直しただけで終わらせない。**必ず全ファイルを走査して古い番号の残りを探す。

### 6. 顧客に渡す書類は「空欄の型」と「1社目の実績」に分ける

**回答や実データが入った書類は、2社目に渡せない。**

- **空欄の型** … フローに載せる。他社にそのまま渡せる。1社目固有の記述は0件にする
- **1社目の実績** … その会社の設計図にぶら下げる。回答・実データを保持する

**⚠️ 2つの `flow-subject` を同じにしない。**同じだと印・相談・承認がどちらか一方に混ざる。

### 7. 読んだ印は「確認する人」にだけ出す

印＝**この資料のどこまでを確認したかのしおり**。毎回頭から読み直さないためのもの。

| その人の役割 | 印 | なぜ |
|---|:---:|---|
| **確認する人** | **要る** | どこまで見たかを覚えておく必要がある |
| **回答する人・入力する人** | **要らない** | 回答そのものが資料に残るので、しおりが要らない |

宣言：`<meta name="flow-check-sides" content="運営">` または `content="運営,顧客">`

**⚠️ 判断の軸は「社内／社外」ではない。**社外に見せる資料でも、相手が確認する立場なら印は要る（例：地図・承認対象のフロー）。**回答欄を持つ資料の顧客側には要らない。**

### 8. 機械で確かめる

```bash
python keiei_os_map_update.py --design    # 番地の食い違い・迷子・貼り忘れ・渡したものの抜けを検査
python keiei_os_map_update.py --drift     # 材料のずれを検査
```

`--design` が出す4つの合格表示。**1つでも欠けたら直してから次へ進む。**

| 表示 | 何を確かめたか |
|---|---|
| 迷子はありません | 全部の書類が構造図から辿れる |
| ファイル名と番地: 一致 | ファイル名の番号がいまの居場所と合っている |
| フローへの貼り付け: 漏れなし | ステップに属する書類が、親フローの「使うもの」欄に出ている |
| **相手に渡したもの: 全部に番地あり** | **渡したものが、全部フローの中に居場所を持っている** |

あわせて手で確認する。

- **A3縦1枚に収まるか**（後述）
- **相対リンクの切れが0件か**（全ファイル走査）
- **`flow-subject` の重複が0件か**

### 9. 配って、記録する

VPSへ配置 → `--mark` でずれを解消 → 判断はDEC一覧へ。
**⚠️ ファイル名を変えたら、携帯のホーム画面ショートカットが切れる。**必ず報告に書く。

## A3縦1枚は必ず測る

**目分量で判断しない。**1行足すと2枚になることがある。**専用の道具がある。**

```bash
python flow_pages.py                      # 全部の枚数を数える
python flow_pages.py <ファイル>            # 1枚だけ
python flow_pages.py --height <ファイル>   # あと何mm削ればよいかを出す（上限420mm）
```

（`情報/AIツール・自動化/flow_pages.py`。Chromeで実際に印刷して数えるので、実物と同じ判定になる）

**超えたときの直し方：**

1. **どの行が原因かを切り分ける**（追記を1つずつ外した変種を作って測る）。**行の高さは、その行でいちばん高い欄で決まる**ので、狙いを外すと削っても効かない
2. **重複している説明を削る**（同じことが2か所に書いてある所を探す）
3. **ラベルを短くする**（⑤-1-3a 見立てシート → 3a シート。番号の前半は行の文脈から自明）
4. **同じ欄の項目を1行にまとめる**

**⚠️ 足すなら同じだけ削る。**限界（420mm）に張り付いている資料がある。
