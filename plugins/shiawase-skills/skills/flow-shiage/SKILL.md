# 業務フローの仕上げ（/flow-shiage）

**フローは骨組み。実際に動くと書類が生まれる。その書類を「使う瞬間の場所」へ貼り戻すと、フロー1枚が「何をするか」と「そのとき使う実物」の両方を持つ。**
担当者が変わっても、ステップを上から辿るだけで必要な書類に全部届く。**これが属人性を消すということ。**

書類を「種類」や「フォルダ」で整理してはいけない。**新しい人は「どのフォルダを見ればいいか」を知らない。**
だが「いま自分はステップ3にいる」は誰でも分かる。**使う瞬間で並べれば、知識のない人でも辿れる。**

---

## 仕上がった状態（これが目標）

```
◆ 経営設計図 ⑤商品設計
✓ ⑤-1      経営OSの導入の流れ          ← 押せる（フロー本体）
   ⑤-1-1   許可と題材の記録            ← 文字だけ。一段下げる
   ⑤-1-3a  見立てシート
   ⑤-1-3b  実物の依頼文
   ⑤-1-6a  地図（受注から収支まで）
   ⑤-1-6b  打ち合わせの進め方
   ⑤-1-7   月次の数字づくり
   ⑤-1-8   社長面談の段取り

◆ フロー本体（⑤-1）の「使うもの」欄
   ステップ3： 借りた管理資料／設定⑥ 入口＋合言葉／📄 3a シート／📄 3b 依頼文
   ステップ6： 会社の地図／📄 ⑤-1-6a 地図／📄 ⑤-1-6b 打ち合わせの進め方
```

**番号を見れば居場所が分かり、フローを開けばその場で書類に飛べる。**両方が揃って初めて仕上がり。

---

## 手順

### 1. 実際に何が生まれたかを洗い出す

そのフローの全ステップについて、**実際にやった行動と、そこで生まれた／使った書類**を並べる。

**⚠️ 「相手に送るものが無い」＝「アクションが無い」ではない。**
社内で許可を取る・題材を決めるのも立派なステップ1の行動で、その記録は残っている。

### 2. 番号を決める

| 種類 | 番号 | 例 |
|---|---|---|
| フロー本体 | 経営設計図の箱の中の位置 | ⑤-1 |
| そのステップで使う付属品 | **親の番号 + ステップ番号** | ⑤-1-6（ステップ6で使う） |
| 同じステップに2つ以上 | **枝番 a/b** | ⑤-1-6a／⑤-1-6b |

**⚠️ 番号は経営設計図上の居場所を指す**（DEC-20260730-010）。フォルダ構成とは切り離す。

### 3. 経営設計図に登録する

箱の `data-files` に1行足す。書式は **`パス|表示名|段|ステップ番号`**。

- **段**＝2 で一段下がる（親の下に入る）
- **ステップ番号**を書くと、番地が「親の番地-ステップ番号」になり、**自動でリンクなしの文字だけ表示**になる

**⚠️ 表示名に古い番号やカッコ書きの説明を入れない。**番号は機械が前に付ける。

### 4. フロー本体の「使うもの」欄に貼る

| 記号 | 何に使うか |
|:---:|---|
| **📄** | **押せるもの。**`業務フロー/` にあってサーバーに配ってある書類だけ |
| **・** | **押せないもの。**記録（正本）の中にある .md など。名前と番号だけ出す |

**⚠️ 押せないリンクを作らない**（共通ルール項15・16）。携帯から開けるのは配ってある書類だけ。
**⚠️ 押せるようにしたいなら、`業務フロー/` のHTMLにする。**ただし他社にも使い回す書類のときだけ。1社限りの記録はHTML化しない。

### 5. 名前を5か所そろえる

**ここで必ず事故が起きる。**2026-07-30に同じ抜けを3回繰り返した。

| # | 直す場所 |
|:---:|---|
| 1 | ファイル名 |
| 2 | `<title>` |
| 3 | `<h1>` |
| 4 | フローの「使うもの」欄の**表示ラベル**（href だけ直して表示を忘れる） |
| 5 | 経営設計図の `data-files` の**表示名** |

**⚠️ リンク先（href）を直しただけで終わらせない。**必ず全ファイルを走査して古い番号の残りを探す。

### 6. 顧客に渡す書類は「空欄の型」と「1社目の実績」に分ける

**回答や実データが入った書類は、2社目に渡せない。**

- **空欄の型** … フローに載せる。他社にそのまま渡せる。1社目固有の記述は0件にする
- **1社目の実績** … その会社の設計図にぶら下げる。回答・実データを保持する

**⚠️ 2つの `flow-subject` を同じにしない。**同じだと印・相談・承認がどちらか一方に混ざる。

### 7. 読んだ印は「確認する人」にだけ出す

印＝**この資料のどこまでを確認したかのしおり**。毎回頭から読み直さないためのもの。

| その人の役割 | 印 | なぜ |
|---|:---:|---|
| **確認する人** | **要る** | どこまで見たかを覚えておく必要がある |
| **回答する人・入力する人** | **要らない** | 回答そのものが資料に残るので、しおりが要らない |

宣言：`<meta name="flow-check-sides" content="運営">` または `content="運営,顧客">`

**⚠️ 判断の軸は「社内／社外」ではない。**社外に見せる資料でも、相手が確認する立場なら印は要る（例：地図・承認対象のフロー）。**回答欄を持つ資料の顧客側には要らない。**

### 8. 機械で確かめる

```bash
python keiei_os_map_update.py --design    # 番地の食い違い・迷子を検査
python keiei_os_map_update.py --drift     # 材料のずれを検査
```

あわせて手で確認する。

- **A3縦1枚に収まるか**（後述）
- **相対リンクの切れが0件か**（全ファイル走査）
- **`flow-subject` の重複が0件か**

### 9. 配って、記録する

VPSへ配置 → `--mark` でずれを解消 → 判断はDEC一覧へ。
**⚠️ ファイル名を変えたら、携帯のホーム画面ショートカットが切れる。**必ず報告に書く。

## A3縦1枚は必ず測る

**目分量で判断しない。**1行足すと2枚になることがある。**専用の道具がある。**

```bash
python flow_pages.py                      # 全部の枚数を数える
python flow_pages.py <ファイル>            # 1枚だけ
python flow_pages.py --height <ファイル>   # あと何mm削ればよいかを出す（上限420mm）
```

（`情報/AIツール・自動化/flow_pages.py`。Chromeで実際に印刷して数えるので、実物と同じ判定になる）

**超えたときの直し方：**

1. **どの行が原因かを切り分ける**（追記を1つずつ外した変種を作って測る）。**行の高さは、その行でいちばん高い欄で決まる**ので、狙いを外すと削っても効かない
2. **重複している説明を削る**（同じことが2か所に書いてある所を探す）
3. **ラベルを短くする**（⑤-1-3a 見立てシート → 3a シート。番号の前半は行の文脈から自明）
4. **同じ欄の項目を1行にまとめる**

**⚠️ 足すなら同じだけ削る。**限界（420mm）に張り付いている資料がある。
