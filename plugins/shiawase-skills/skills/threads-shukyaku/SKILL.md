# Threads自動集客システム構築スキル（/threads-shukyaku）

noteで販売している商品を、Threadsの毎日自動投稿で見込み客に届けるシステムを**一式まるごと構築する**手順の正本。
2026-08-12〜14に構築した1号機（リボン向け・建築学生就活ノウハウ）で実証済み。コードのひな形は `templates/` にある。

## 完成形（1日の流れ）

毎晩21:00 記事台帳＋時期＋履歴からGeminiが翌日の朝・夕2本を生成→携帯通知 → 持ち主が承認ページで**承認/却下/修正**（1日数分）→ 朝7:30・夕方（実験計画の時刻）に**承認済みだけ**自動投稿（1枚目＝続きが気になる形で切る／2枚目＝返信に続き。URLは書かない）→ 反応データを毎日自動取得 → 毎週月曜8:00に週次レポート。

|:---|:---|

| 投稿時刻 | 朝7:30／夕17:30（→実験で21:00） |
| システムを使う人（承認する人） | note著者本人 |

## 前提（共通基盤・すでにあるもの）

- VPS `root@210.131.223.173`（鍵認証・nginx・certbot・cron。URLは `<名前>.210-131-223-173.sslip.io` 方式）
- Gemini APIキー（無料枠・Google AI Studio）。**有料記事の本文はGeminiに渡さない**（無料枠は学習利用の可能性があるため）
- 通知は ntfy.sh（無料・購読トピック方式）
- Metaアプリは**インスタンスごとに1つ**作る（管理は伊藤さんのFacebookでよい。投稿アカウントとの接続はThreadsテスター招待で行う）

## 構築手順

### Phase 1：記事台帳（システムの唯一の材料）

1. 記事一覧を取得：RSS `https://note.com/<id>/rss`（25件まで）＋ API `https://note.com/api/v2/creators/<id>/contents?kind=note&page=N`（全件・価格・スキ数）
2. 分析エージェント2〜3体に分担させ、各記事を8項目で台帳化：URL／区分（無料・有料）／テーマ／解決する悩み／対象／**有効な時期**／重要ポイント／**Threads投稿の切り口（型付きで3つ以上）**／note誘導文脈
3. **有料記事は本人にチャットへ全文貼り付けてもらい**、「有料部分の概要（Geminiに渡さない）」「投稿で明かしてよいこと」「明かさないこと（売り物の核心）」の3段で線引きを追記する
4. 台帳はVault `プロジェクト/進行中/<プロジェクト名>/` に置き、VPSへ `ledger.md` として転送する
5. 読者の年間カレンダー（月→状況→優先記事）と編名マップ（記事→◯◯編）をこの時点で設計する

### Phase 2：コード配置

`templates/` の5ファイルを `/var/www/<インスタンス名>/` にコピーし、**次の定数を書き換える**：

| ファイル | 書き換える箇所 |
|:---|:---|
| generate_posts.py | SEASON（月別カレンダー）／SEASON_ARTICLES（月別優先記事）／HEN_MAP（編名）／SERIES_TITLE／build_prompt内のペルソナ・発信理念・**文体見本（本人の実投稿を貼る）** |
| approval_app.py | PORT（空きポート）／NOTE_URL／evening_hour（時刻実験計画）／通知clickのURL |
| threads_poster.py | evening_hour／通知clickのURL |
| report_weekly.py | 通知clickのURL／時刻実験の説明文 |
| insights_fetcher.py | 変更不要 |

`.env` に置くもの：GEMINI_API_KEY／AIKOTOBA（管理者用,利用者用のカンマ区切り）／TEST_MODE=1／SECRET（openssl rand -hex 16）／NTFY_TOPIC（管理者用,利用者用）／THREADS_APP_ID／THREADS_APP_SECRET。`chmod 600 .env`

### Phase 3：公開（systemd・nginx・cron）

1. systemdサービス（approval_app.pyをRestart=alwaysで常駐）
2. nginx：`<名前>.210-131-223-173.sslip.io` → 127.0.0.1:ポート。certbotでHTTPS化。**計測リンク用に `note-<名前>.…sslip.io` も同じ転送先で作る**（1号機は `note.…` を使用済みのため2号機以降は名前を変える）
3. cron5本：21:00生成／7:30朝投稿／17:30と21:00夕投稿（evening_hourが計画外をスキップ）／20:50反応取得／月曜8:00週次レポート

### Phase 4：Threads接続（本人のアカウント操作が必要）

パスワード入力と「同意/許可」ボタンは本人（または伊藤さん）、それ以外の画面操作はClaudeがブラウザで実行する。

1. developers.facebook.com でアプリ作成（ユースケース＝**Threads APIにアクセス**・ビジネスポートフォリオはリンクしない）
2. 権限4つを追加：threads_basic／threads_content_publish／threads_manage_replies／threads_manage_insights
3. アプリの役割→**Threadsテスター**に投稿アカウントを招待 → 本人がThreadsの「設定→アカウント→ウェブサイトのアクセス許可→招待」で承認
4. ユースケース設定ページの「ユーザートークン生成ツール」でトークン生成（**普通のChromeで**。承認ページ用ブラウザだと小窓が開かない）。⚠️ トークンは**コピーボタン**でコピーさせる（画面をなぞると●●●のままコピーされる事故が1号機で発生）
5. トークンはメモ帳経由で受け取り `token.json` に保存（`{"access_token":…,"refreshed_at":ISO日時}`）。**チャットに本文を貼らせない・画面に表示しない**
6. `GET /v1.0/me?fields=id,username` でユーザー名一致を実測 → TEST_MODE=0

### Phase 5：計測と引き渡し

1. プロフィールに貼る計測リンク（`https://note-<名前>.…sslip.io/go`）を本人に渡して張り替えてもらう
2. 取扱説明HTMLを /zukai で作成（初期設定＝ntfy購読と承認ページの2つだけ／毎日の使い方／困ったときは。合言葉入りのため本人にのみ渡す）
3. Vaultに引き継ぎノートを作り、プロジェクト一覧に登録する

## 投稿の型（1号機・2号機で確定した仕様・変えるときは本人確認）

- 1枚目冒頭に必ず題名 `【シリーズ名｜◯◯編①】`（編名と通し番号はコードが自動付与。却下分は番号を消費しない）
- 1枚目＝続きが気になるところで切る（320字以内）／2枚目＝返信に続きの本文（400字以内）
- **つなぎの3ルール（2026-08-15追加。抜けると2枚が分断される）**：①1枚目の最後の行は必ず「引き」（問いかけ・言いかけ・意外な一言）で終える。「〜してくれました。」のような完結した報告文で締めるのは禁止 ②2枚目の冒頭1文は1枚目の引きに**直接答える形**で書き始める（一般論から始めない）③時期の話題は流れに馴染む場合に1文まで（唐突に挿入しない）
- **URLは投稿に書かない**（noteはプロフィールから）。「プロフィールのnoteにまとめています」は自然なときだけ
- 見た目ルール：全角24文字折り返しで**各段落の最終行が8文字以上**（生成時に自動検査→違反はGeminiに書き直させる。承認ページのプレビューでも赤警告）
- 表記ルールはインスタンスごとにREPLACEMENTS（機械置換）で保証する（プロンプト指示だけに頼らない）

## 安全装置・運用機能（全インスタンス共通・削らない）

承認なしでは絶対に投稿しない／台帳にない情報は書かない／有料の核心はAIに渡さない／1日4件上限／同一本文の再投稿禁止／エラー時は再投稿せず通知のみ／トークン7日ごと自動更新／不安を煽る表現・過度な営業の禁止をプロンプトに明記

さらにtemplatesに実装済みの運用機能（2026-08-15時点）：
- **Gemini混雑対策**：45秒待ち再試行＋**予備モデル自動切替**（FALLBACK_MODELS）。それでも失敗したら「作れませんでした」を携帯に通知（無音で落ちない）
- **「⚡今すぐ投稿する」ボタン**：承認済み・予定時刻超過・当日分に表示。利用者が自力で復旧できる
- **通知の名札**：全通知タイトルに【インスタンス名】を付ける（複数ブランドで取り違えないため）。投稿完了通知もあり
- 週次レポートに「全投稿の明細」（投稿ごとの閲覧・いいね・返信・再共有）／レポートと承認ページは相互リンク／レポート生成直前に最新インサイトを取り直す

## スキルの鮮度を保つ決まり（2026-08-15・伊藤さん指摘により追加）

**本体（VPS上のコード）を改善したら、同じ作業の中でこのスキルの templates/ と SKILL.md を更新して push する。**別の作業にしない。スキルの更新漏れは、次のインスタンスにバグとして伝染する（2026-08-15に「つなぎルール」等7件の反映漏れが実際に起きた）。
