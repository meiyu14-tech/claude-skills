# 黒字化の打ち手スキル（/kuroji）

**赤字の既存事業を、黒字に戻すための打ち手を全部並べて、どれから手をつけるかまで決める。**

新しく何かを始める話ではない。**いま動いていて、いま損が出ているもの**を対象にする。

## このスキルの狙い

赤字の相談を受けるたびにゼロから考えると、**思いついた順に並ぶ**。
思いついた順は、たいてい「やりやすい順」であって「効く順」でも「急ぐ順」でもない。

この型が守るのは次の3つ。

| # | 守ること | なぜ |
|:---:|:---|:---|
| 1 | **止まると取り返せないものを先に置く** | 資金ショートと、人が抜けて技術が消えること。この2つは黒字化より先に来る。順番を間違えると、後の打ち手が全部効かなくなる |
| 2 | **効き目を金額で出す** | 「廃棄を減らす」だけでは動けない。**年間いくら効くか**を出して、必要額と突き合わせる |
| 3 | **全部やらせない** | 打ち手を20個渡すと1個も進まない。**必要額に届く3つ**を選ばせる |

## 入力

`/kuroji` の引数：業種・売上・いまの状況（テキスト、またはファイルパス）
引数がない場合、次の3つだけ聞く（**これ以上は聞かない**・共通ルール項10）。

1. 何の商売か（業種・店舗数）
2. 年商はいくらか
3. 赤字はいくらか（分からなければ「分からない」でよい）

## 作成前（必須）

1. 共通ルール項0に従い、**目的・完成形・保存先の3点を提示してOKを得る**
2. 実際の試算表・レジデータを見ているかを確認する。**見ていないなら、そう書く**（後追いを発生させない第2条）

⚠️ **実データが無くても作る。ただし「想定」と明記する。**
数字が揃うまで何も出さないのは、相手を待たせるだけで役に立たない。
**想定で組んで、置き換える場所を指定する。**

## 資料の構成（7つ。順番を変えない）

冒頭に共通ルール項14の「この書類の使い方」ブロックを置く。その下に次の7つを必ず全部入れる。

### 1. 赤字の形を決める

**その業種で赤字になるとき、どこが膨らんでいるか**を先に置く。
業種ごとの目安は `references/gyoshu-mesyasu.md` を読む。

- 想定P/Lを1枚の表にする（売上100%から順に、営業利益まで）
- **どの費目が目安を超えているか**を、色や太字ではなく**数字の並び**で見せる
- ⚠️ 実データが無いときは、表の上に「想定・実データ未確認」と入れる

### 2. 最初の7日で集める数字

**この資料の中でいちばん先に使われる部分。**箇条書きのチェックリストにする。
どの業種でも共通するのは次の骨組み。業種に合わせて言葉を変える。

- 月次試算表 直近12か月
- 主要原価の率（月ごと）
- 人件費と総労働時間
- 固定費（家賃・リース・水道光熱）
- 借入残高と毎月の返済額
- 日々の売上と客数（または受注件数）
- 単価と1件あたりの数量
- 商品・サービスごとの売れた数
- 捨てている・作り直している金額
- 時間帯／曜日ごとの売上
- 売上の内訳（直販・卸・元請など）

### 3. 埋め方の試算（この資料の核心）

**打ち手ごとに、年間いくら効くかの表を作る。**列は次の4つに固定する。

| 打ち手 | 年間の効き | 大きさ（棒） | 効き始めるまで |

- **必ず合計を出し、合計は満額では出ないと書く**
- **必要額（＝いまの赤字額）を同じ表に並べる**
- 表の下に「**この中の3つが当たれば届く**」と明記し、**効き始めが早いもの／投資が要らないもの**を先に勧める

⚠️ **金額は必ず計算過程が追える置き方にする。**「値上げ7%（客数3%減を見込む）→ +240万」のように、**前提を1行で添える。**

### 4. いましかできないこと（時限のあるもの）

**買収・引き継ぎ・着任の直後にしかできないこと**を並べる。ここを飛ばすと後が全部効かない。
最低限、次の3つは必ず入れる。

1. **作り方・やり方を文書と動画に残す**（属人化した技術が消えると取り返せない）
2. **キーパーソンと面談して処遇と役割を先に出す**（引き継ぎ直後の離職が最大の損失）
3. **13週間の資金繰り表**（黒字化より先に、資金ショートを防ぐ）

### 5. 打ち手の全カタログ

分野ごとに分けて並べる。**順番ではなく分類**なのでA・B・Cの記号を使う（番号は使わない）。
各分野に「効き ◎／○」と「効き始めるまで」を付ける。

どの業種でも必ず入れる分野：

| 記号 | 分野 |
|:---:|:---|
| A | 捨てている／作り直している分を減らす |
| B | 原価を下げる |
| C | 人件費を下げる（**人を減らさずに。工程を整えてから配置を変える**） |
| D | 固定費・光熱費を下げる |
| E | 単価と客数を上げる |
| F | 捨てない売上をつくる（数が先に決まる販路） |
| G | 商品と値段を決め直す |
| H | 数字を見る仕組みをつくる |
| I | 人と役割 |
| J | お金・資金繰り・補助金 |

⚠️ **Iの「人と役割」には、伊藤さんの役割定義を必ず通す**（CLAUDE.md）。
「やる気がどこにあるかを聞いて、やる気に合ったやり場を渡す」を具体的な行動として書く。
人を数字として扱う書き方（「◯人削減」を先に出す）はしない。

### 6. やめる・閉じるの判断

**増やす話と同じ回数、減らす話を書く。**最低4つ。

- 何か月やって改善しなければ止めるか（期限を数字で）
- 赤字の取引先・不採算の商品ラインをどう扱うか
- 止めた判断は日付と理由を残す（同じ話が半年後にまた出るため）

### 7. 90日の順番と、毎日見る5つの数字

- 90日を4区切りにする（止血 → 穴をふさぐ → 粗利を作る → 伸ばす）
- 毎日見る数字は**5つに固定する**。それ以外は月1回でよいと書く

## 書き方の決まり

- **そのままの言葉で書く。**比喩を使わない（「出血を止める」ではなく「資金が尽きるのを防ぐ」）
- 専門用語は初出で必ず開く（「FL比率（原材料費＋人件費）」）
- どの幅で開いても横にはみ出さない（CLAUDE.md ⓪HTML成果物の作り）
- **断定には確かめ方を1行添える。確かめていないものは「未確認」と書く**（後追いを発生させない第2条）

## 出力（⚠️ ここが2026-09-06に変わった）

**分析は1回。書き出すのはJSONだけ。HTMLは書かない。**

```
1回の分析
   ↓
BUN-YYYYMMDD-NNN.json     ← AIが書くのはこれだけ
   ↓  python bun_html.py BUN-….json
BUN-YYYYMMDD-NNN.html     ← 機械が作る
   ↓  python bun_kensa.py BUN-….json
検査5件（5件PASSしないと出さない）
```

⚠️ **HTMLを手で書かない。**書くと「同じ分析から2つ出す」が崩れ、2回考えることになる。
機械が作るので、**HTMLにJSONに無い言葉が入ることが原理的に起きない。**

### JSONに必ず入れるもの（4者間データ契約・境界1）

| 欄 | 中身 |
|:---|:---|
| `bun_id` | `BUN-YYYYMMDD-NNN`。再分析のたびに新しく発番し、**前の分析は書き換えない** |
| `ban`／`mae_bun_id`／`prj_id` | 何回目か／前の分析／どのプロジェクトか（初回は後ろ2つ空） |
| `moto_sodan` | 人が言った一文をそのまま |
| `taisho_an`／`gyoshu` | 対象（**案**。正式な対象は②が持つ）／業種 |
| `jitsu_data_kakunin` | 実データを見たか（見ていなければ `false`） |
| `mokuteki`／`mokuhyo_an` | 目的／目標（**案**）。それぞれ `shirushi` を付ける |
| `genjo` | 想定P/L。`shirushi` と `moto`（どこから置いたか）を必ず付ける |
| `kasetsu` | 原因仮説。`KA-NN`。**`kensho` にどの調査で確かめるかを必ず書く** |
| `shigoto_kouho` | 仕事候補。`CH-NN`（調査）／`IM-NN`（即実行）／`SE-NN`（候補施策）<br>各に `shurui`（A／B／C-1／C-2）・`fukagyaku`・`gate`・`zentei`・`riyu` |
| `shihyo_an` | 指標。`KP-NN`。**`shurui` で「目標」か「目安」かを必ず分ける**<br>**`moto_shigoto`**（どの仕事の結果として測るか）と **`kanryo_hantei`**（下記）も必ず入れる |
| `chushi_joken`／`phase`／`gate`／`saibunseki_joken` | やめる条件／進める順番（**次へ進む条件つき**）／人が判断する3か所／再分析の条件 |
| `hikiwatashi` | ②へ渡すIDの一覧と、**渡さないもの**の一覧 |
| `chui` | 想定であること・補助金の要件・人員削減の順番 |

**印（`shirushi`）は5つだけ：**`jijitsu`（事実）／`sotei`（想定）／`kasetsu`（仮説）／`mikakunin`（要確認）／`sanko`（業種の目安）

### 目標は「人が読む文」と「機械がくらべる決まり」の両方を出す

⚠️ **目標には種類がある。**全部を固定の数値にしない。指標ごとに `mokuhyo_rule` を出す。

| 種類 | いつ使うか | 形 |
|:---|:---|:---|
| `kotei` | 固定値・上限・下限 | `{"kata":"kotei","enzan":"<=","atai":5,"tani":"%"}` |
| `han-i` | 範囲 | `{"kata":"han-i","shita":4000,"ue":5000,"tani":"円/人時"}` |
| `kijun` | **別の事実を基準にする** | `{"kata":"kijun","enzan":">=","kijun":"損益分岐点売上","tani":"円/日"}`<br>基準に足し引きするなら `"chosei":50` |

⚠️ **基準がまだ無くてもよい。**「損益分岐点売上」がまだ出ていなくても、そう書く。
システムが「**比較基準未取得：損益分岐点売上 が必要**」と出し、**事実が揃った時点で自動的に比較できるようになる。**
**0や仮の数を入れない。**

### 指標と目標が食い違っていないか、必ず確かめる

⚠️ **測るものと目標の単位が違っていたら、指標が間違っている。**

例：「捨てた金額（円/日）」に「売上の5%以下」という目標は付かない。
**5%は廃棄率の目標**なので、**指標を分ける**：

| 指標 | 種類 | 中身 |
|:---|:---|:---|
| 捨てた金額（円/日） | `jijitsu` | 目標を持たない**事実**。ほかの指標の材料 |
| 売上（円/日） | 目標あり | 事実でもあり、材料でもある |
| **廃棄率（%）** | `mokuhyo` | **算出**：`{"shiki":"waru","bunshi":"KP-01","bunbo":"KP-02","bairitsu":100}` |

⚠️ **台帳には事実だけを測らせる。**割り算は仕事の基本がやる。
⚠️ `shurui` は3つ：`mokuhyo`（目標）／`meyasu`（目安・目標ではない）／`jijitsu`（事実・目標なし）

### 完了の判定（`kanryo_hantei`）は、指標ごとに必ず出す

**測るのに必要な事実が揃って、値が確定したか**を書く。**人にあとから書かせない。分析のときにAIが出す。**

⚠️ **「目標を達成したら完了」にしない。**測定の完了と、成果の達成は別物。

| 指標 | 完了の判定（例） |
|:---|:---|
| 捨てた金額 | 対象日の廃棄金額が集計でき、値が確定したら完了 |
| 売上 | 対象日の売上実績が確定したら完了 |
| 客数 | 対象日の客数が確定したら完了 |
| 客単価 | 対象日の売上と客数が揃い、客単価を算出できたら完了 |
| 1人1時間あたりの売上 | 対象期間の売上と総労働時間が揃い、値を算出できたら完了 |

**書き方：**「〜が揃い（確定し）、〜を算出できたら完了」。<strong>何が揃えば測り終わりか</strong>だけを書く。

### A／B／C-1／C-2 の分け方

| 印 | 意味 | 判定 |
|:---:|:---|:---|
| **A** | 調査・測定 | 測るだけ。運営を何も変えない |
| **B** | 今すぐ安全に実行 | **不可逆でない・お金が動かない・外部に出ない・方針を変えない、の4つをすべて満たす** |
| **C-1** | 数字を待たないが個別承認が要る | 外部・金銭・不可逆・方針変更を伴うが、実測を待たなくてよい |
| **C-2** | 実測後に判断 | 前提の調査が終わるまで出さない |

⚠️ **1つの文に複数の性質が混ざっていたら、分けて出す。**
例：「製造責任者と面談して処遇と役割を出す」→ **面談する（B）** と **処遇を決める（C-2・前提はB）** に分ける。

## 保存と報告

| 項目 | 決まり |
|:---|:---|
| 保存先 | `プロジェクト/再建/BUN-YYYYMMDD-NNN.json`（HTMLは同じ名前で機械が作る） |
| 検査 | **`python bun_kensa.py BUN-….json` が5件PASSしないと出さない** |
| 渡し方 | **VPSへ置いてURLを渡す**。伊藤さんはリモート操作のため、手元のファイルは見えない。⚠️ map直下ではなく `shiryo/` へ置く（`--deploy` が直下を消すため） |
| 報告 | 本文には**①判断してほしいこと ②済ませたこと ③URL**の3つだけ（共通ルール項18）。分析と根拠は資料側に置く |

**報告のサマリーに必ず出すもの（隠さない・共通ルール項20）：**

1. **実データを見たか／想定か**
2. **必要額と、それに届く3つの打ち手**
3. **時限のあるもの（いましかできないこと）**
4. 判断してほしいこと

## やってはいけないこと

| ⚠️ | 理由 |
|:---|:---|
| **人員削減を最初の打ち手にしない** | 先に人を減らすと作れる量が減り、売上が落ちて赤字が深くなる。順番は「工程を整える → 手が余る → 配置を変える」 |
| **打ち手を全部やらせない** | 20個渡すと1個も進まない。必要額に届く3つを選ばせる |
| **想定の数字を実測のように書かない** | 置き換える場所を必ず指定する |
| **補助金の要件を断定しない** | 年度ごとに変わる。「申請前に最新の公募要領で確認」を必ず添える |
| **投資・財務の助言として書かない** | 出すのは事業運営の打ち手。資金調達・金融商品の判断は専門家へ回す |
